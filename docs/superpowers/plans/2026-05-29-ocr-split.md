# ocr.ts 拆分实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `src/attachments/ocr.ts`（1582 行逻辑 + 513 行 inline 测试）按职责拆成 `src/attachments/ocr/` 文件夹下的聚焦模块，行为零改动、公共导出面不变、消费方零改动。

**Architecture:** 编译器导向的剥离重构。先 `git mv` 成 `ocr/index.ts`（specifier `./attachments/ocr` 自动解析到 `ocr/index.ts`，消费方不动），再逐个把职责簇从 index.ts 剥离到同级文件。每个簇给出锚点函数；其私有 helper 跟随，跨簇共享 helper 进 `lines.ts`。`npm run lint`（含 `lint:tsc`）是"无遗漏符号、无循环依赖"的精确 oracle，`npm run test` 是"行为不变"的精确 oracle。

**Tech Stack:** TypeScript、esbuild、Vitest（`import.meta.vitest` in-source 测试）、ESLint + `scripts/check-unused-code.mjs` + knip。

**全程铁律：**
- 函数体**逐字搬运，不编辑**。每个任务只做：剪切符号 → 调整 import → 更新 barrel re-export → 搬对应 `it()` 测试。
- 不改算法、阈值、正则；不重命名任何公共导出符号；不动无关格式。
- 不新增 `try/catch`、不加 fallback、不新增依赖或抽象层。
- 每个任务结束时 `npm run lint` 与 `npm run test` 必须全绿。测试总数基线 **1248**（其中 ocr 内 28 个 `it`），拆分后必须仍是 1248。
- **相对 import 深度**：`ocr/` 下的文件比原 `attachments/ocr.ts` 深一层。跨出 attachments 的路径用 `../../`（`../../logger`、`../../domains`、`../../lang/locale/en`），同级 attachments 内用 `../ocr-runtime`。可直接参照已修好的 `ocr/index.ts` 头部。
- **测试归属（实现期修正）**：in-source `it()` 只在**直接调用被移函数**时才跟随该函数搬走（如 Task 2 的 merge 测试直接调用 `mergePositionAttachmentOcrResults` 等，可搬）。若 `it()` 通过留在 index 的 orchestrator `extractPositionAttachmentOcrResultFromRecognition` / `extractPositionAttachmentOcrResultFromImageRecognition` 间接测试（MetaTrader / TradingView / pixel 的几乎所有用例都是如此），则**必须留在 index.ts**——把它们搬进新模块会让模块 import index，与 index→模块 形成循环、挂 `lint:deps`。Tasks 3/4/5 的提取模块默认**不带测试块**。
