LucrJournal 不会自动同步券商历史。仓位、账户、标的和复盘内容以当前 Vault 中的文件为准；联网能力只负责取得网页内容、标的元数据和图表行情，或完成登录。

## 先分清本地与联网能力

| 能力 | 数据从哪里来 | 是否需要联网 | 断网时会怎样 |
| --- | --- | --- | --- |
| 手动创建和编辑记录 | 当前 Vault | 否 | 可以继续记录和复盘。 |
| 截图 OCR | 随插件安装的本地模型和你提供的图片 | 否 | 可以识别、复核并写回仓位。 |
| 新闻来源 | 你填写的网页和远端正文提取服务 | 是 | 标题或正文可能无法取得；仍可手动创建新闻和填写正文。 |
| 标的搜索与元数据 | 本地内置目录、当前 Vault、TradingView | 远端增强需要 | 本地候选和已有标的仍可用；远端类型与图标可能缺失。 |
| 图表行情 | Yahoo 或账户平台对应的交易所 | 是 | 图表可能没有行情或显示加载失败；本地仓位不会被删除。 |

这些远端结果都不是本地记录的真源。断网不会把已经保存的 Markdown 变成不可用数据。

## 从网页导入新闻

在`新闻`中填写`来源链接`时，LucrJournal 会访问该网页。创建新闻时，它会尝试取得可用标题和正文；直接网页没有可用标题时，还会尝试远端回退服务。

编辑已有新闻的来源后，界面会打开`导入来源内容`：

1. 核对`来源链接`是正确的网页。
2. 阅读确认窗口；不想改正文时点击`取消`。
3. 点击`导入`，把远端页面转换成 Markdown 正文。
4. 导入后检查标题、段落和链接是否适合长期保留。

如果远端正文加载失败，新建新闻仍会保留为空正文；编辑已有新闻时可以取消或稍后重试。

> [!WARNING]
> `导入来源内容`会覆盖新闻当前正文。确认窗口提示已有内容时，先复制仍需保留的手写笔记。

## 从截图识别仓位字段

OCR 可以从粘贴、上传或拖入的第一张受支持图片开始，也可以从 Vault 中已有的仓位图片附件开始。识别模型和运行文件随插件安装，运行时不会下载替代文件；任何一个必需文件缺失时，OCR 会失败。

识别结果只包含`名义价值`、`入场价`、`出场价`、`止损`和`目标价`。推荐流程：

1. 打开 OCR 导入，粘贴、上传或拖入交易截图。
2. 等待`确认 OCR 结果`出现。
3. 对照原图逐项修改识别值。
4. 点击`应用到当前仓位`。

提交前，识别值不会写入仓位。关闭复核窗口也不会创建附件；成功应用时，确认后的字段和原图附件才会一起写入。

> OCR 可能识别错小数点、价格和数量。必须对照原图人工复核；它也不会根据价格关系替你判断`做多`或`做空`。

## 标的搜索怎样使用远端数据

选择标的时，LucrJournal 先使用当前 Vault 中的标的和本地内置目录。输入不属于本地目录的代码时，它会向 TradingView 查询候选，并尝试补充`类型`和图标。

远端查询失败、返回空结果或没有可用类型时，本地创建仍会继续。已有标的始终从 Vault 读取，不依赖 TradingView；因此断网时可以继续使用它们。新建后仍应按 [[accounts-and-symbols]] 核对类型、手续费和合约单位。

远端搜索成功结果只在当前运行期间缓存一小时。失败结果不会写入缓存，也不会固化到本地记录。

## 图表行情从哪里来

图表只在能解析出受支持来源时请求行情：

- 期货忽略账户平台，使用 Yahoo 行情。
- 加密货币现货或合约使用账户平台对应的 Binance、Bybit 或 OKX。
- 标的链接、类型或账户平台无法解析时，不发起行情请求。

行情只用于图表，不会自动写入仓位字段。非空行情会缓存 15 分钟；空结果不会缓存。交易所返回限流时会等待后重试，其他网络或响应错误会让本次图表加载失败。

> [!TIP]
> 断网时先继续写仓位和复盘。恢复网络后重新打开图表或再次搜索标的即可，不需要重建本地记录。

本地文件的完整范围见 [[local-files-and-markdown]]。
