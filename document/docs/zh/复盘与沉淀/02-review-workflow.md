## 一次复盘要得到什么

一次完整复盘要留下三类结果：这笔交易实际发生了什么、当时为什么这样做、下一次要检查什么。先核对事实，再解释原因，最后才改策略手册。

下面的流程串起 `概览`、`仓位`、仓位详情、上下文和 `策略手册`。它不要求一次处理全部记录，只要求结论能回到真实仓位。

## 第一步：确定复盘样本

1. 打开仪表盘，在页头选择 `全部账户` 或一个具体账户。
2. 在 `概览` 选择 `周`、`月`、`季`、`年` 或 `全部时间`。
3. 从异常日期进入 `仓位`，或直接打开 `筛选仓位`。
4. 按 `状态`、`方向`、`置信度`、`账户`、`交易对`、`策略手册`、`新闻` 或 `分析` 缩小范围。
5. 选择 `显示结果`，再按 `收益` 或 `开仓时间` 排序。

筛选条件与搜索同时生效。先回答一个问题，例如“这个月某个账户的做多为什么亏损”，不要把所有维度一次堆在一起。

> [!TIP]
> 日常复盘优先看刚结束的仓位和明显偏离计划的仓位。周期复盘再看同一策略手册或同一上下文下的一组样本。

## 第二步：核对每笔交易的事实

选择仓位行进入详情，依次检查：

1. `状态`、`出场价` 和 `平仓时间` 是否一致。
2. `入场价`、数量、`手续费` 和 `净利润` 是否完整。
3. `目标价`、`止损`、`计划 R:R` 和 `实际 R:R` 是否符合当时计划。
4. `置信度` 是否仍能代表入场时的判断，而不是事后结果。

仓位只要 `状态` 为平仓，或存在 `平仓时间`，统计就把它视为已平仓。两者可以暂时不一致，所以复盘时要一起核对。字段和公式的完整口径见 [[position-details]] 与 [[position-lifecycle]]。

## 第三步：补齐证据和上下文

在仓位详情完成三件事：

1. 在 `笔记` 写这笔交易独有的计划、执行偏差和结果。
2. 在 `附件` 补交易截图；需要时再使用 OCR。操作见 [[attachments-chart-ocr]]。
3. 关联真正会复用的 `新闻`、`关键位`、`Confluence` 或 `市场分析`。边界见 [[context-notes]]。

不要为了让记录看起来完整而创建上下文。只出现一次的内容先留在 `笔记`；第二次需要引用时再独立保存。

## 第四步：读懂统计口径

上下文和策略手册的汇总沿真实文件链接反向查找仓位。页面上的数字不一定使用同一批样本。

| 指标 | 纳入哪些仓位 |
| --- | --- |
| `关联仓位`、`交易笔数` | 全部已解析到当前上下文或策略手册的仓位，包括持仓中的仓位、零利润仓位和利润缺失的仓位。 |
| `胜率` | 只使用已平仓且 `profit` 为非零数字的仓位；没有样本时显示 0。 |
| `净利润` | 只合计同一批已平仓且 `profit` 为非零数字的仓位。 |
| `最大盈利`、`最大亏损` | 只从同一批表现样本中取极值；没有样本时不显示数值。 |

例如，某策略手册显示 `10 笔`，其中只有 5 笔已平仓且净利润为非零数字。这 5 笔里有 3 笔盈利，页面会显示 60% 胜率。60% 是 3 ÷ 5，不是 6 ÷ 10。

> [!NOTE]
> `仓位` 表的状态筛选与表现统计还有一处边界差异：`盈利` 要求 `profit >= 0.01`，`亏损` 接受 `profit <= 0`。因此已平仓且 `0 < profit < 0.01` 的仓位不在两个筛选中；`profit = 0` 会进入 `亏损` 筛选，却不会进入胜率、净利润和最大盈亏统计。

## 第五步：写下结论

先把单笔结论写进仓位的 `笔记`。一个可执行的结论至少包含：

- 事实：计划和实际发生了什么。
- 原因：偏差来自市场变化、判断错误还是执行错误。
- 下一次动作：入场前要确认或禁止什么。

只有结论在多笔仓位中重复出现时，才把它沉淀到策略手册：用条件分组表达检查阶段，用 Confluence 表达可重复出现的条件组合。创建和关联方法见 [[playbooks-and-criteria]]。

## 日常和周期复盘怎样分工

| 节奏 | 处理范围 | 完成标志 |
| --- | --- | --- |
| 每日或每次交易后 | 刚结束或刚更新的仓位 | 事实、证据、上下文和单笔结论完整。 |
| 每周或每月 | 同一账户、标的、策略手册或上下文的一组仓位 | 找到重复模式，并决定是否更新条件或 Confluence。 |

> [!TIP]
> 周期复盘的产出不是更多笔记，而是更少、更明确、能在下一笔交易前执行的检查项。
