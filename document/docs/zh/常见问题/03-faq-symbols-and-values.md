这组问题解释标的字段、派生值、仓位生命周期和创建后的约束。

## 类型识别错了

**标的代码能保存，但 `类型` 和我选的不一样。**

`类型` 是推断出来的，不是从代码里解析出来的。

未命中内置目录的六位大写代码会被推断为 `加密货币现货`。而当 `类型` 为空或无法识别时，仓位计算又会回退到 `加密货币合约`。两种情况都不报错。

> [!TIP] 怎么做
> 添加标的后，在 `标的` 列表核对 `类型`、`手续费` 和 `合约单位`。

→ [[symbol-types]] · [[symbol-fields]]

## 手续费不能填 0

**`手续费` 填 0 保存不了。**

三种手续费模型都拒绝 0。没有手续费时应该留空，而不是填 0。

同一个 `手续费` 字段在不同类型下含义不同：

| 类型 | `手续费` 的含义 |
| --- | --- |
| `加密货币现货`、`加密货币合约` | 名义价值的百分比 |
| `期货` | 每张合约的金额 |
| `CFD差价合约` | 每手的金额 |

→ [[symbol-types]]

## 盈亏比对不上

**界面显示的盈亏比和我手算的不一样。**

==计划和实际 R:R 都会重新计算风险，忽略你手填的 `风险` 值，而且都不计手续费。==

它们按方向、`入场价`、`止损`，以及 `目标价` 或 `出场价` 重算，不读取已保存的 `风险` 或 `净利润`。公式只使用一份 `入场价`，没有平均入场模型。

→ [[position-fields]] · [[position-lifecycle]]

## 旧派生值没清空

**改了数量或价格，但 `名义价值` 还是旧的。**

算不出新值时，旧值会被保留，而不是清空。

`数量`、`入场价` 或 `合约单位` 失效后，如果公式得不到新结果，旧的 `名义价值` 会留在原地；`手续费` 无法重新派生时同理。它们会继续参与 `净利润` 计算。

> [!WARNING] 怎么做
> 改坏或移除源字段后，逐项核对 `名义价值`、`手续费`、`净利润` 和 `风险`。

→ [[position-details]] · [[position-fields]]

## 平仓三字段不同步

**`状态`、`平仓时间` 和 `出场价` 互相对不上。**

这三个字段不是强制同步的一组。

写入 0 或负数的 `出场价` 同样会触发平仓；清空 `出场价` 不会自动重新开仓。

> [!TIP] 怎么做
> 平仓或重新开仓之后，逐项核对这三个字段。

→ [[position-lifecycle]]

## 方向不可修改

**`方向` 选错了，改不回来。**

`方向` 在创建后不可修改，任何触及它的更新都会被整次拒绝。

> [!TIP] 怎么做
> 删除错误的记录，用正确的 `方向` 重新创建。

→ [[record-first-position]]
